## What it does

1. **`scripts/extract-mockup-spec.ts`** (new): parses the mockup's `#appData`
   JSON + `__ASSETS__` base64 blobs and emits everything below. Hard-asserts:
   4 sections / 10 groups / 33 topics (5/15/9/4 per section) / 132 standard
   resources / 15 extras / 297 templates / the 33-row `ELEMENT_MAP`
   (`topic_slug → elements.slug`) resolves each element exactly once. Also
   asserts per-kind card copy is constant (it ships as app constants in PP3,
   not DB rows) and every optimized image lands under 600 KB.
2. **`docs/workspace-spec.json`** (generated, committed): the full IA spec —
   pages/heros, journey cards, sections → groups → topics (with
   `elementSlug`), per-topic standard-doc/extra/template filename manifests
   (the CMS upload hints + the PP3 display source for template codes).
3. **Migration `0027_platform_ia`** (hand-written, up + down): additive only.
   - New tables `platform_sections` (5 rows: About + 4 toolkit pages; slug
     fixed by CHECK), `platform_groups` (10), `platform_topics` (33 —
     `element_id UNIQUE NOT NULL FK → elements` is the integrity spine),
     `platform_extras` (15; `resource_id` NULL until CMS upload). All RLS
     default-deny, ZERO client policies (the 0011 posture).
   - `resources` gains `code` (backfilled `T01`-style from the
     `<slug>/tNN-` ingest path convention — deterministic, self-consistent)
     and `doc_key` (overview/guide/checklist/watch; partial unique per
     element — the future home of the 132 standard docx uploads, PP6).
   - New member RPCs `get_platform_sections/topics/extras` — SECURITY
     DEFINER, `set search_path = ''`, `stable`, `where public.is_approved()`,
     revoke public/anon + grant authenticated (exact 0011 pattern).
   - `get_resources()` **DROP + CREATE inside the same transaction** with
     `code`/`doc_key` **appended** (no column removed/reordered) — deployed
     code reads named fields and ignores extras, so old prod code is
     unaffected; no window where the RPC is missing.
4. **Migration `0028_platform_seed`** (GENERATED by the script, up + down):
   idempotent upserts keyed on stable natural keys — sections `slug`, groups
   `(section_slug, slug)`, topics `element_id` via `elements.slug` subselect
   (a wrong slug fails the NOT NULL loudly instead of seeding wrong), extras
   `(topic_id, title)`. Down deletes only the seeded IA rows.
5. **Verification scripts** `0027_verify_TEST_db_only.sql` (role-simulated:
   approved sees 5/33/15/299, pending sees zero rows everywhere;
   rollback-only) + `0027_verify_PROD_safe_readonly.sql` (plain selects, for
   the owner's prod apply at the PP2 merge gate).
6. **47 committed assets** under `public/assets/workspace/` (11MB total):
   33 topic photos + 4 section photos (from the owner's 92MB PNG masters,
   now gitignored under `docs/source-assets/design-refs/workspace/`) + 5 page
   heroes + 5 misc ornaments (base64-only in the mockup) — all via sharp
   (mozjpeg, ≤2000px, each under 600 KB). The brand lockup is deliberately
   NOT extracted (`public/assets/logo/` stays canon).
7. **Trackers**: `ROADMAP.md` gains the Stage 4 block (PP1–PP7 scope + exit
   gates + the DB expand→contract timing); `PROJECT-STATUS.md` §1 flips to
   PP1 active, §5 gains D-PP-a (public terminology drift, parked) + D-PP-b
   (the four owner decisions).

## Review checklist (the gating questions)

- **A. The map.** `ELEMENT_MAP` in `scripts/extract-mockup-spec.ts` — is each
  of the 33 `topic_slug → element_slug` pairs plausible against the element
  titles listed in the brief's Context? (This is THE thing that must not be
  wrong; everything else is recoverable.)
- **B. 0027 additive safety.** Could any statement in `0027_platform_ia.up.sql`
  affect the deployed app before PP2 ships? (Old code calls `get_resources()`
  via PostgREST `rpc()` and reads named fields; the widened return appends
  columns only. Nothing else old code calls is touched.)
- **C. RLS posture.** Four new tables: RLS enabled, zero policies, reads only
  via `is_approved()`-gated SECURITY DEFINER RPCs with pinned search_path and
  revoke-then-grant. Any leak path for anon/pending?
- **D. Seed idempotency.** Re-running 0028 must change nothing the second
  time; the down files must revert cleanly (0028 down before 0027 down).
- **E. The generated SQL.** Spot-check escaping (titles contain `'`? none do,
  but verify), the `on conflict` targets exist as constraints in 0027, and
  the subselect keys (`elements.slug`, group `(section_slug, slug)`).
- **F. Repo hygiene.** No gitignored file staged (mockup, PNG masters,
  `.env.local`); asset weights sane; no `src/` change anywhere in the diff;
  typecheck/lint/build green (46 routes) — re-run yourself.
